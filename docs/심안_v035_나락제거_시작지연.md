창현님이 12장 플레이 중 짚은 두 가지를 고친 판입니다.

## 1. 12장 '나락의 심연' — 검은 구덩이 지형 제거

- **무엇이 문제였나**: v0.32 §6.1 지형 규칙 엔진이 12장에 `terrain: { kind: 'pit' }`(나락 가장자리)를 걸어 두었습니다.
  맵에 보라 테두리의 검은 타원이 5개씩 그려지고, 그 가장자리(1.2m 띠)에 서 있으면 영웅이 0.5m/초로 중심 쪽으로 끌려갔습니다.
- **어떻게 고쳤나**:
  - `v2/js/game.js` 12장 정의를 `terrain: { kind: 'none', name: '없음' }`으로 바꿨습니다(소개 카드 줄은 '지형 · 없음 — 기본 규칙으로 첫 획을 익힙니다').
  - `pit` 규칙 코드 자체를 지웠습니다 — `zoneAt()`의 pit 갈래, `onTick()`의 끌림 처리, `drawTerrain()`의 검은 타원/테두리 그리기, `TERRAIN_CFG.pit`, `terrainInit`의 `dragT·pitN`, QA `terrainProbe` 목록의 pit, `warpHeroToZone`의 pit 예외.
  - 1~11장 규칙(잔해·대숲·달빛·안개·눈밭·뿌리·종루·혈석·물길·성벽)은 그대로입니다.
- **확인**:
  - 12장 `zoneAt(x, z)` 격자 전수 6,561점(±40m, 1m 간격) → 지형 0건(이전에는 pit 띠가 잡혔습니다).
  - 2장 같은 격자에서 `rubble` 377점이 그대로 잡혀 대조 확인.
  - 12장 실플레이 150초(적 58기) 프레임: `S.terrain.counts` 빈 객체, `dragT` 0, 콘솔·페이지 에러 0건.
  - 스크린샷: `reports/심안_v12_나락제거_QA/stage12_play.png`, `stage12_play150.png`, `stage12_intro.png`.

## 2. 출전 버튼 뒤 멈춤 — "게임이 시작되기 전에 왜 이렇게 오래 멈춰있어?"

### 원인
출전을 누른 순간에 세 가지 무거운 일이 몰려 있었습니다.

1. **셰이더·텍스처 예열**(`prewarm.js`): 이 판에 나올 수 있는 재질 76종을 그때 처음 링크하고 텍스처 수십 장을 한 프레임에 업로드.
2. **바닥 판석 베이킹**(`inkbake.js groundSet`): 512×512(26만 픽셀)에 보로노이+fbm 4종+노멀맵을 **동기** 계산.
3. **청크 월드 재구축**: `startRun`이 `chunks.reset(0,0)`으로 9청크를 통째로 다시 지었습니다.

### 고친 것
- **타이틀 유휴 예열** (`game.js titlePrewarm`): 타이틀이 한 번 그려진 뒤부터 `warmShaders(10)`을 **프레임당 10ms 예산**으로 백그라운드 진행. 바닥 판석도 선택한 막의 4장을 한 프레임에 하나씩 미리 굽습니다. 판이 시작되면 즉시 손을 뗍니다.
- **텍스처 업로드 분산** (`prewarm.js`): `finish()`가 수십 장을 한 번에 올리던 것을 **프레임당 3장**으로 나눴습니다.
- **바닥 판석 512 → 256** (`inkbake.js`): 계산량 1/4. 픽셀 반경 상수(이음매 2→1px·16→8px·26→13px)와 노멀 강도(2.3→1.15)를 해상도에 맞춰 보정해 화면 인상은 유지했습니다.
- **청크 재구축 생략** (`inkchunks.js world.reset`): 같은 자리·같은 장에서 판을 다시 시작하면 9청크를 다시 짓지 않고 부순 항아리만 되살립니다.
- **계측 훅**: `GPv2.perfLog()`가 `beginStage`·`switchMap`·`switchMap.chunks`·`chunkWorld.build`·`chunksReset`·`startRun`·`warm` 소요 시간을 남깁니다(최근 40개). `?nowarm=1`은 예열을 끄는 탈출구입니다(QA·약한 기기).

### 실측 (Playwright Chromium 390×844, 소프트웨어 GL, `?nowarm=1`로 GL 컴파일 제외)

| 구간 | v0.34(`0ff3c81`) | v0.35 | 비고 |
|---|---|---|---|
| 바닥 판석 + 청크 9개 구축 (`switchMap.chunks`) | 202 ms | **57 ms** | 12장, 256으로 줄어든 판석 베이킹 포함 |
| 장 무대 전체 (`switchMap`) | 677 ms | **521 ms** | 파노라마·재질 포함 |
| 판 시작 동기 작업 (`startRun`) | 185 ms | 213 ms | 오차 범위(같은 경로) |
| 소개 카드 → 판 시작 대기 | 카드 2.6초 뒤 예열·맵 대기 | 타이틀에서 이미 끝나 있음 | 아래 참고 |

- 셰이더 링크는 이 환경(소프트웨어 GL)에서 레시피 하나가 0.5~1초라 **절대값을 기기 수치로 쓸 수 없습니다**. 대신 배치가 바뀐 것을 확인했습니다: 타이틀에서 아무것도 누르지 않은 상태에서 `warmInfo().phase`가 `idle → building → compile`로 진행되고, 베이킹 대상 레시피는 총 76개입니다. 클릭은 이 예열을 기다리지 않고, 클릭 시점에는 이미 끝나 있거나 남은 양만큼만 남습니다.
- 기기에서 예상되는 효과: 512² 베이킹이 폰에서 대략 0.4~0.8초 걸리던 것이 1/4로 줄고, 출전 순간의 예열·청크 재구축이 사라집니다.
