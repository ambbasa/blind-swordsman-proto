## 1. 번개 인식 회귀 (§2.1)

**문제**: v0.27의 "좁은 번개" 완화 뒤, 손 떨림이 있는 **세로선·가로선이 번개로 읽히는** 회귀가 있었다.
번개는 자동 조준이라, 세로선을 그었는데 엉뚱한 혼령으로 돌진했다.

**구현** (`v2/js/gestures.js`): 번개는 다음 네 조건을 모두 만족할 때만 인정한다.

| 조건 | 규칙 | 근거 |
|---|---|---|
| ① 폭 비율 | 획 진행 방향에 수직인 폭 / 길이 ≥ **0.18** | 손 떨림은 대개 0.05~0.12 |
| ② 꺾임 각도 | 손떨림을 한 번 걸러낸(smooth 3) 경로에서 **60° 이상 꺾임 2곳 이상** | 완만한 물결은 번개가 아니다 |
| ③ 곧은 정도 우선 | 끝점 거리/경로 길이 ≥ **0.9**면 번개 후보에서 제외, 축 흡수가 우선 | 직선은 그은 대로 가는 편이 덜 억울하다 |
| ④ 애매할 때 | 세로선·가로선과 번개가 **0.08 이내**로 붙으면 직선 | 덜 위험한 쪽 |

①②는 `scoreBolt()` 안(`boltGeometry`), ③④는 `recognize()`에서 처리한다.
`GPGestures.boltGeometry`를 QA용으로 노출했다.

**측정** (합성 획 510개, 같은 시드·같은 모음으로 v0.28 인식기와 비교):

| 항목 | v0.28 | v0.29 | 수용 기준 |
|---|---|---|---|
| 세로선 → 번개 | 6.7% (3/45) | **0%** | 1% 이하 ✅ |
| 가로선 → 번개 | 6.7% (3/45) | **0%** | 1% 이하 ✅ |
| 좁은 번개(폭 20px) 인식 | 100% | **98.3%** | 90% 이상 ✅ |
| 동그라미 인식 | 86.7% | **86.7%** | 85% 이상 ✅ |
| V / 네모 / 탭 | 97.8 / 100 / 100% | 97.8 / 100 / 100% | 유지 ✅ |

- 세로선이 아예 읽히지 않는 비율(`none`)은 v0.28과 같다(흔들림 9px 구간 6/45). 이번 변경이 만든 손실은 없다.
- 기물 무늬(△ ◡ @) 인식률도 변하지 않았다(삼각 77.8%, 반달 57.8%, 소용돌이 100% — v0.28과 동일).

**결정**: 설계안 §2.2의 "v0.27 완화를 인정하고 로드맵 8장을 고칠지"는 **인정 + §2.1 보완**으로 정리했다.
`docs/심안_v024_개선사항.md` 8장에 그 관계를 적었다. (설계안이 추천한 방향이다.)

## 2. 인식 회귀 시험 자동화 (§2.3)

`tests/unit/gestures/`

| 파일 | 내용 |
|---|---|
| `corpus.js` | 합성 획 생성기(UMD). 무늬 10종 × 흔들림 3단계(3·6·9px) × 크기 3단계(90·124·160px) × 기울기 5단계(-20°~+20°) + 폭 20px 좁은 번개 60개 = **510개**, 고정 시드 `20261129` |
| `baseline.json` | 승인된 혼동 행렬과 §2.1 수용 기준. 칸이 하나라도 달라지면 시험 실패 |
| `run.py` | 획을 인식기에 넣어 혼동 행렬을 만들고 기준선과 비교, 수용 기준도 함께 잰다 |
| `ci-workflow.yml` | 푸시마다 돌릴 워크플로(복사해서 `.github/workflows/gestures.yml`로) |
| `real/` | 실제 손 획 자리(아직 비어 있음) |
| `README.md` | 재는 법·갱신 법·왜 Vitest가 아닌지 |

`tests/unit/gestures/ci-workflow.yml`이 푸시마다 이 시험을 돌리는 워크플로다. **아직 `.github/workflows/`에 넣지 못했다** — 이 저장소에 연결된 GitHub App 토큰에 `workflows` 권한이 없어 푸시가 거부됐다. 저장소 주인이 Actions를 켜고 그 파일을 `.github/workflows/gestures.yml`로 복사해 커밋하면 켜진다(README에 명령).

```bash
python3 tests/unit/gestures/run.py            # 검사
python3 tests/unit/gestures/run.py --update   # 기준선 갱신(의도한 변경일 때만)
```

**설계안과 다르게 한 것 두 가지**

1. **Vitest 대신 Playwright**: 설계안은 `tests/unit/gestures/`(Vitest)를 적었지만 이 저장소에는
   Node/npm 빌드 도구가 없고(정적 사이트), 이 작업 환경에도 node가 없다. 같은 생성기·같은 기준선·같은
   수용 기준을 이미 쓰는 Playwright(Python)로 돌린다. `corpus.js`는 Node에서도 바로 쓸 수 있게 UMD다.
2. **실제 손 획 모음 없음**: 설계안은 사람 5명 × 무늬 20회를 모으라고 했지만 실제 사람이 필요하다.
   `tests/unit/gestures/real/` 폴더와 형식만 만들어 두었다.

## 3. 타격감 (§3.1)

| 사건 | 전 | 후 |
|---|---|---|
| 일반 명중 | 히트스톱 0 | **0.035초**, 한 획에 여러 명중이어도 1번 |
| 한 획의 정지 예산 | — | **0.06초** (명중·처치가 몇 번이든) |
| 처치 | 0.06 | 0.06 + 먹 번짐 반경 **×1.4** |
| 파훼(경직·기세 붕괴 중 절단) | 0.06 | **0.10** + 보스 혼령 무늬가 금빛으로 깨지는 연출 |
| 기모으기 받아치기 | 0.15 | 0.15 + **화면 가장자리 금빛 번쩍임 0.2초** |
| 칼 튕김 | 없음(뜯만 띄움) | **0.03초** + 짧고 높은 쇳소리(`whiff(true)`) |

- **에셋 변경**: `assets/v2/fx-ink/code/inkParticles.js`의 `kill()`에 `scale` 옵션을 넣어 번짐 반경만 키운다.

## 4. 공정성 (§3.4)

**다섯 원칙을 모두 구현했고, 피할 수 없는 공격 넷에 두 번째 대응을 붙였다.**

| 원칙 | 구현 |
|---|---|
| 예고 | 피해 2 이상 공격은 예고 0.6초 이상 + 색과 소리 (기존 수치가 모두 만족: 기모으기 2.2, 내려찍기 1.0, 영창 4.5, 결계 수축 10, 은신 기습 0.7, 자폭 0.85초) |
| 대응 수 | 기모으기: **기물 뒤에 숨으면 피해 1**(주인공·보스 선분 0.8m 안에 기물). 영창: **3개 중 2개 이상 끊었으면 피해 1**. 결계 수축: **기둥 2개 이상 부수었으면 피해 1** |
| 첫 실패 완화 | 이 판에서 처음 맞는 "피할 수 없는" 큰 피해는 **1** |
| 재시도 | 기모으기의 이른 탭은 **판당 한 번 봐준다**. 두 번째부터 실패 |
| 연쇄 금지 | 피격 무적(0.8초) 중에는 다음 공격이 **발동하지 않는다** |

- 가짜 분신 방울 간격 1.1 → **0.9초**(읽기 쉽게). 가짜 반격 1은 그대로.

**측정**(같은 보스에 상태만 갈아 피해만 격리):

| 경우 | 피해 |
|---|---|
| 기모으기 · 기물 뒤 | **1** |
| 기모으기 · 기물 없음 | 2 |
| 영창 · 3개 중 2개 끊음 | **1** |
| 영창 · 0개 끊음 | 2 |
| 결계 수축 · 기둥 2개 부숨 | **1** |
| 결계 수축 · 기둥 0개 | 2 |
| 첫 강제 피해 | 2 → **1** (두 번째부터 2) |
| 피격 무적 중 강제 피해 | **0** (판정 "막아냈다") |
| 이른 탭 1번째 / 2번째 | 봐줌(잠금 없음) / 실패(잠금) |

## 5. 기물 역공 (§4.1)

- 보스가 **예고 중**(`telegraph`·`slamTele`·`volleyTele`·`kiai`)일 때 기물로 일섬하면 기물이
  먹 궤적이 되어 보스에게 날아간다 → **경직 1.0초 + 참 +12 + 기세 1칸**.
- 예고가 아니면 예전처럼 참 +3.
- 역류 가능한 순간에는 기물의 보랏빛 고리가 **금빛**으로 바뀐다(예고 색 체계와 같은 말).
- 한 번의 예고에 역류 1번. `breakTotem()`이 예고 중이면 `reflectTotem()`으로 분기한다.

**측정**: 예고 중 기물 일섬 → 경직 1.00초, 기세 3→2, 참 0→12, 판정 "역류 명중!".
경직 중 베기 → 2칸("파훼!"). 같은 예고에서 두 번째 기물 → 참 +3만, 추가 경직 없음.
걷기 중 기물 → 참 +3, 경직 없음.

## 6. 빈틈 고리 (§4.2)

- 걷는 보스 발밑에 **빈틈 고리**: 1.6초에 걸쳐 차오르고, 다 차면 하얗게 번지며 짧은 방울 소리.
- **빈틈 선입력**: 빈틈이 0.5초 안에 열릴 때 그은 획은 튕기지 않고 예약되어, 고리가 다 차는 순간
  보스에게 자동으로 날아간다(최대 0.5초 대기). 예약된 획은 그 방향(조준 콘)과 상관없이 보스에게 난다.
- 첫 걷기 무적과 "첫 패턴을 보라"는 안내는 그대로.

**측정**: 고리 진행 0.10 → 1.00이 1.60초에 걸쳐 차오르고, 열리는 순간 방울이 울리고 번짐 0.45초.
빈틈 0.35초 전에 그은 획 → 예약 → **0.35초 뒤 자동 일섬, 보스 순서 1칸**("빈틈!").
빈틈 1.4초 전에 그은 획 → 예약하지 않음(예전처럼 튕김).

## 7. 기기 데이터 기록 (§13)

새 파일 `v2/js/telemetry.js`. 이벤트 8종을 **기기 안에만** 쌓는다(개인정보 없음, 최근 2,000개).

| 이벤트 | 필드 |
|---|---|
| `stage_start` | 장, 모드, 판 번호 |
| `stage_end` | 결과, 시간, 남은 체력, 별, 처치, 최대 콤보, 레벨, 보스 상태 |
| `death` | 원인(맞은 공격 문구·원귀 종류), 체력, 보스 상태, 시각 |
| `stroke` | 의도 무늬, 인식 결과, 1·2등 점수, 길이, 실패 이유 |
| `card_pick` | 제시 3장, 고른 카드, 레벨 |
| `boss_pattern` | 패턴, 결과(성공·회피·파훼), 시작 표시 |
| `parry` | 대상(일반·기모으기), 시각 오차(ms), 결과 |
| `fps` | 장, 평균, 저점, 화질 단계 |

- 일시정지 창에 **[기록 보내기: 끔/켬]**(동의 표시)과 **[기록 내보내기]**(JSON 파일 다운로드)를 두었다.
  서버가 아직 없어, "보내기"는 동의만 남기고 실제 전송은 하지 않는다(설계안도 "동의한 경우에만"이라고 적었다).
- 저장 위치: `localStorage` 키 `gesture-proto.v2.telemetry`. 20개마다·판이 끝날 때 쓴다.

**측정**(한 판): `stage_start` 1, `stroke` 1, `card_pick` 3, `boss_pattern` 10, `parry` 2,
`stage_end` 1, `death` 1, `fps` 1 — 내보내기 JSON 파싱 성공(n=20), 저장 키 생성 확인.
