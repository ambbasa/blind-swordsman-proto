# 심안 v0.38 — 주인공·원혼·보스 캐릭터 파츠 리그 (에셋 · 60fps 모션)

기준 커밋 `74ef3e8`(v0.37) · 대상 `v2/` · 화풍 기준 `/workspace/downloads/siman_style_4_silk_diorama.png`

## 1. 무엇을 바꿨나

v0.37 은 배경·소품을 비단 병풍 디오라마 PNG 로 바꿨지만, 캐릭터는 아직 `inkchars.js` 가 캔버스에
붓으로 그린 256px 시트(8fps 프레임 교체)였다. v0.38 은 주인공·원혼·보스를 **실제 그림 파츠**로 올리고,
프레임 교체 대신 **관절별 파츠 변형**으로 60fps 연속 모션을 만든다.

  겹칠 때 사각 안개가 되고, 좁게 굽으면 게임 크기(50~150px)에서 사라진다.

## 3. 코드

- 신규 `v2/js/inkcharart.js` — 모듈 로드 즉시 `manifest.json` + 19장을 `Image.decode()` 로 비동기 로드.
  하나라도 실패하면 `rigReady()` 가 false 로 남고 art.js 는 기존 코드 드로잉으로 폴백한다(폴백 유지).
- 신규 `v2/js/inkchars3d.js` — 파츠를 **빌보드 메시**로 세운다. Sprite 대신 Mesh 를 쓰는 이유:
  three r170 의 스프라이트 셰이더는 `scale.x = length(modelMatrix[0].xyz)` 로 부호를 버려서
  음수 스케일 반전이 먹지 않는다. Mesh 는 지오메트리를 피벗만큼 옮겨 두고 `rotation.z` 로 관절 회전,
  `group.scale.x = ±1` 로 좌우 반전한다.
- `art.js` — `makeChar` 진입에서 리그를 먼저 시도하고(hero/afterimage/zombie/boss), 없으면 기존 경로.
  `tickChar` 는 리그가 있으면 `tickFigure` 로 넘긴다. 공개 훅: `setCamera·kickChar·tintChar·
  setCharOpacity·setCharOrder·setAuraColor·rigInfo`.
- `game.js` — 부팅에서 `art.setCamera(three.camera)` + 캐릭터 파츠 프리로드(최대 2.5초 대기, 실패 시 폴백),
  피격 시 `art.kickChar`, 피격 플래시·상태이상 틴트를 파츠 전체에, 잔상은 `setCharOpacity`,
  QA 훅 `rigInfo`/`rigTrace`/`rigBench`.
- 렌더 순서: 다리(base−0.04) → 띠(−0.02) → 몸통(base) → 머리(+0.03) → 칼팔·무기(+0.05), 아우라(−0.06).
  영웅은 base 8, 원혼·보스는 2.

## 5. 남은 것 / 알려진 한계

- 보스 실루엣은 원화의 검은 연기 비중이 커서, 밤 무대에서 윤곽이 연기 덩어리로 읽힌다.
  스킨(§9.2)이 rim 색을 덮어쓰므로 악귀다운 진홍 테는 '외형' 선택에 달려 있다.
- 혼령(도깨비불)은 v0.19 시안 C 그대로 — 다음 후보.
- 돌덩이 귀신은 코드 드로잉 유지.
- 실기기 60fps 체감은 이 환경(소프트웨어 GL, 1~2fps)에서 잴 수 없다. 리그 CPU 비용과 드로우콜
  증가분(캐릭터당 3~5메시 + 아우라)으로 대신 보고한다.
