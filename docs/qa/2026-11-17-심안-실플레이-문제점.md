# 『심안』 최신 버전 실플레이 문제점 전수 점검

## 0. 결론 요약

- **게임이 멈추거나 진행이 막히는 P0 결함은 0건**이었다. 12장 구성·보스 결계·기물·참(斬)·패링·영창·봉인·진화·아이템까지 이번에 실제로 조작해 확인한 경로는 모두 동작했고, 콘솔·페이지 에러도 전 구간 0건이다.
- **가장 큰 격차는 "1~4장에서만 새 보스전이 돈다"**는 점이다. 5~12장 보스 8개는 여전히 `걷기 → 예고 → 돌진 → 경직` 한 가지 순환만 돌아, 12장 내내 같은 보스를 8번 상대하는 느낌이 난다(기획서 `design/gdd/blind-swordsman.md` 3.14에 `[구현]`으로 적혀 있는 미완 상태).
- **보스가 걷는 동안에도 그냥 벨 수 있어** 신규 패턴을 보기 전에 보스가 죽는다. 1장 보스는 자동 플레이 기준 **등장 후 3.2초 만에 사망**했다(3개 무늬).
- **처음 켠 사람에게 "무엇을 그려야 하는지" 알려 주는 화면이 없다.** 첫 10초 튜토리얼(기획서 v0.24 4번)과 `참 준비 (O 그리기!)` 안내가 모두 미구현이라, 참(斬)의 존재 자체를 알 방법이 없다.
- **HUD가 390px 폭에서 넘친다.** 참 게이지 라벨이 `참 / 20`처럼 두 줄로 쪼개지고, 버프가 겹치면 엽전·콤보가 화면 밖으로 잘린다(측정: 행 폭 469px vs 표시 영역 362px).

### 1.2 시험 환경

- Playwright + `chrome-headless-shell`, 뷰포트 **390×844**(모바일, `has_touch=true`), 별도로 **1440×900**(데스크톱)·**844×390**(가로) 1회씩.

- **헤드리스 소프트웨어 렌더(SwiftShader) 한계**: 390×844에서 **평균 3.5fps**. 게임 시간은 벽시계의 약 0.2배로 흐른다. 상태 전이는 `qa.timeScale`로 게임 시간을 진행시켜 확인했고, **FPS·로딩 시간 수치는 실기기 성능이 아니다.**

## 2. 문제 목록

### P0 — 치명(진행 불가) : **0건**

게임을 진행할 수 없게 만드는 결함은 찾지 못했다. 보스전에서 기물이 모두 부서져도 2.5초마다 다시 서고, 참·패링·영창·봉인이 모두 입력 경로로 동작하며, 판이 끝나면 결과 카드에서 다음 장으로 넘어간다.

---

### P1-1. 5~12장 보스 8개가 v0.26 이전의 단일 돌진 순환을 그대로 쓴다

- **증상**: 1~4장 보스는 장마다 다른 패턴(기모으기·내려찍기·분신·은신·탄막·영창·결계 수축)을 쓰지만, **5장부터 12장까지 8개 보스는 `걷기(기본 4.5초) → 예고 → 돌진 → 경직` 한 가지만 반복**한다. 예고 색 고리·대응 문구("피하라/받아쳐라/그려라")·기세 마름모·봉인 마무리도 5~12장에는 표시되지 않는다(패턴 목록이 없으면 `drawBossPat`가 조기 반환).
- **근거**: `v2/js/game.js` STAGES 정의에서 `boss.patterns`가 존재하는 장은 1~4장뿐(195·212·230·248행), 5~12장은 268·286·304·322·342·360·378·396행 모두 패턴 키 없음. `bossPatList()`(3909행)가 `null`을 돌려주면 `stepBoss()`는 구 순환으로 간다. 기획서도 `design/gdd/blind-swordsman.md` 334행에 "5~12장 보스는 아직 예전 돌진 순환을 씁니다. [구현]"으로 적혀 있다.
- **실플레이 인상**: 120초 넘게 진행하는 2·3막에서 보스전이 가장 단조롭다. 반대로 1막은 4장 만에 모든 신규 패턴을 다 보여 준다(난이도·재미 곡선이 1막에서 꺾인다).
- **제안**: 5~8장은 기존 패턴 재조합(돌진+기모으기→내려찍기), 9~12장은 2페이즈 조합으로 채우고, 최소한 `patterns: ['charge','kiai']`라도 넣어 예고 색·기세 UI가 후반에도 보이게.

### P1-2. 보스가 걷는 동안 그냥 벨 수 있어 신규 패턴을 보기 전에 죽는다

- **증상**: 보스는 `walk` 상태(2.6초)에 피격·절단에 완전히 무방비다. 순서를 빨리 베면 예고·패턴을 한 번도 못 보고 클리어된다.
- **측정**: 1장 자동 플레이에서 **보스 등장 60.3초 → 사망 63.5초(3.2초)**. 무늬 3개(예고 1.35초·돌진 0.45초)짜리 보스인데 `charge` 한 번만 보고 끝났다.
- **근거**: `stepBoss()` 3553행 이하 `walk` 분기에는 피해 무시 조건이 없고, `cutSpirit()` 3126행은 `state==='seal'|'sealing'`일 때만 절단을 막는다. 기획서 16장 남은 질문 4번에 "보스가 걷는 동안에도 벨 수 있어서 … 자동 플레이가 그랬습니다"로 이미 인지된 항목.
- **제안**: `walk` 중에는 절단 1회당 1칸이 아니라 '간발' 판정만 주거나, 등장 후 첫 `walk`를 무적(예고 연출)로 두는 방식.

### P1-3. 첫 진입·전투 중 "무엇을 그려야 하는가" 안내가 없다

- **증상**: 1장 시작 화면(부록 `11_stage1_start.png`)에는 **아무 안내 문구가 없다**. 모양 힌트(`SHAPE_HINT`)는 **획이 실패한 뒤 토스트로만** 나오고, 참(斬)을 쓰는 `O`는 화면 어디에도 없다. HUD는 100%가 되어도 `참 준비`라고만 쓴다(`renderCharge()` 511행).
- **측정**: 참 게이지 100 상태에서 DOM 전체를 `O 그리|동그라미|참 준비 (` 로 검색 → **일치 0건**(`ux.json`). 즉 `참 준비 (O 그리기!)`(기획서 v0.24 4.5항)는 미구현.
- **근거**: `docs/심안_v024_개선사항.md` 6장(첫 10초 튜토리얼)·4.5항(참 안내) 모두 설계만 있고 코드에 없음. `practiceSec`/`SHAPE_HINT`만 남아 실패 시 힌트를 준다.
- **영향**: 신규 유저는 가로획 하나만 배운 채 4장까지 가고, 참(斬)·V·번개·기물 무늬는 우연히 그려 봐야 알게 된다. 기획서가 지목한 이탈 요인 그대로다.
- **제안(최소 비용)**: (1) 첫 판 시작 시 참 게이지가 처음 100이 되는 순간 `참 준비 (O 그리기!)` + 1회 토스트, (2) 1장 0~3초에 "그어 보세요" 6자 안내, (3) 타이틀 카드 하단에 `— ㅣ V ⚡ O` 전체 기호 범례.

### P1-4. HUD가 390px에서 넘치고, 참 라벨이 두 줄로 쪼개진다

- **증상 ①**: 참 게이지 옆 라벨이 `참` / `20` 처럼 **두 줄로 갈라진다**(부록 `98_kiai_gold_window.png`, `95_hud_long_state.png`). 2자리 수만 되어도 발생.
- **증상 ②**: `일섬 4·화염Lv3 +얼음12s 종V12s`처럼 수식어가 붙으면 1행이 화면을 넘겨 **엽전 카운터가 잘리고 콤보는 아예 사라진다**.
- **측정**(390×844): 1행 `scrollWidth 469px` vs 표시 폭 `362px`. `#coinLabel` 오른쪽 끝 `417px`(뷰포트 390 초과). `#chargeText`는 `참 / 20`으로 줄바꿈(높이 2배).
- **근거**: `css/style.css` 233행 `#hud .hud-row:first-child { justify-content: space-between; }` + 30행 `#timer,#dashLabel,#coinLabel… { white-space: nowrap; }` → 항목이 양끝으로 밀린 상태에서 길어지면 넘침. `#chargeText`(274행)에는 `white-space: nowrap`·`flex-shrink: 0`이 없어 압축된다. `#hpPips`는 `flex-wrap: wrap`(32행)이라 최대 체력이 오르면 핍이 2줄로 늘어나 2행까지 밀어낸다.
- **제안**: 1행을 `overflow: hidden` + `#comboLabel` 고정폭, `#chargeText { white-space: nowrap; flex: 0 0 auto; }`, 핍은 `flex-wrap: nowrap` + 12개 초과 시 `+N` 표기.

### P1-5. 보스전 이동 수단이 '기물 전용 무늬(△ ◡ @)'뿐인데 배울 곳이 없고, 반달 인식이 방향에 민감하다

- **증상**: 보스가 서면 필드 잡몹이 사라지고 보스 + 기물 3개만 남는다. 주인공은 일섬으로만 움직이므로 **피하는 이동은 기물 무늬(△ ◡ @)를 그려 그쪽으로 돌진하는 길뿐**이고, 보스의 무늬는 보스 몸으로 돌진하는 길만 열어 준다. 그런데 △ ◡ @는 보스전에서 처음 등장하고, 어디에도 설명이 없다(기획서 16장 질문 6).
- **측정**: 실제 터치로 삼각을 그려 기물까지 **3.86m 돌진 성공**(인식 1.00). 반면 **U자로 그린 반달(◡을 아래로 볼록하게)은 인식 0.00(unknown)** — 정식 `arc`(위로 볼록 ∩)만 1.00. 즉 손버릇에 따라 반달 기물로는 이동이 아예 안 된다.
- **측정 2**: 보스전에서 가로획을 그으면 `화면에 그 모양이 없어요` 토스트만 뜨고 아무 일도 없다(정상이지만, 처음 하는 사람에겐 "조작이 먹통"으로 보인다).
- **근거**: `TOTEM_SHAPES = ['tri','arc','spiral']`(34행), `summonDodgeTarget()` 3839행, `finishStroke()`의 기물 분기. `gestures.js scoreArc()`는 `chord`(시작-끝 직선거리 / 전체 길이) 0.4~0.84를 요구해 U자(≈0.3)를 배제한다.
- **제안**: 기물 첫 등장 시 1회 설명 토스트 + 기물 위 글리프에 "그리는 방향" 화살표, 그리고 `scoreArc`에 U자 허용(또는 `arc`를 '반달'이 아니라 '꺾인 갈고리'로 재정의).

### P1-6. 보스가 화면 아래에서 잘리고, 12장은 붉은 안개에 묻힌다

- **증상**: 보스(키 6.5m)가 주인공 쪽으로 다가오면 화면 하단에서 **몸통 절반이 잘린 채** 거대하게 그려져, 예고 동작·자세를 읽기 어렵다(`98_kiai_gold_window.png`, `71_s1_boss_charge_warning.png`).
- **증상 2**: 12장(나락의 심연)은 배경·안개·바닥이 모두 붉은 계열이라 **보스·기물 기둥이 배경에 묻힌다**(`30_s12_boss_arena.png`). 기물은 검은 기둥이라 보랏빛 고리만 보이고 몸체는 식별이 어렵다.
- **근거**: 카메라 고정 오프셋(`CFG.camOff`)과 2.5D 원근 때문에 카메라 쪽(남동) 적이 커진다. 보스전 전용 카메라 줌아웃·보스 실루엣 대비(예: 보스 테두리 광)가 없다. 4장(붉은 달)에서도 같은 현상.
- **제안**: 보스 결계 진입 시 카메라를 1.15~1.25배 줌아웃, 보스에 항상 켜지는 윤곽광(림) 1단 추가, 12장은 안개 밀도(fog 0.042)와 tint를 낮춰 대비 확보.

### P1-7. 3장부터 보스가 경직 후 잡귀를 부른다 — "1:1 보스전"과 어긋난다

- **증상**: 보스가 첫 경직에서 깨어날 때 `adds`만큼 잡귀를 소환한다(3장 2, 4장 3, 11·12장 4). 게다가 v0.26 기물 3개 + 장판(최대 5) + 기물 부적이 겹쳐 결계 안이 붐빈다.
- **측정**: 3장 보스 강제 경직 후 **imp 2마리 생성 확인**(`72_s3_boss_adds_after_stun.png`, `boss_play.json`).
- **근거**: `stepBoss()` 3610행대 `adds` 소환 분기, STAGES 230·248·268~396행 `adds` 값. 기획서 v0.24 3.2(a)는 "전 장 `boss.adds = 0`"을 확정했지만, 현행 GDD 390행은 "그 규칙은 그대로"로 남아 있다(문서 간 충돌).
- **제안**: v0.24 확정안(adds 0)을 따르고, 난전은 기물·장판으로만 만든다. 12장 2페이즈 같은 예외만 `adds`를 남긴다.

## 4. 정상 동작 확인(회귀)

이번 실플레이에서 **문제 없이 동작**한 것들. 이전 QA(v0.23) 항목이 v0.26에서도 살아 있음을 확인했다.

## 5. 검증하지 못한 것

- **실기기 FPS·발열·메모리**: 헤드리스 소프트웨어 렌더(3.5fps)라 판정 불가. 2.5D 소품 725~971개/청크 9개/후처리 5패스 구성은 실기기 확인 필요.
- **5~12장 실제 맵에서의 보스전 전투**: 장을 바꿔 무대를 다시 짓는 비용(`switchMap` → `applyMap` + 셰이더 예열)이 이 소프트웨어 렌더 환경에서 **85초(맵1 재구성)~232초(맵5)** 걸려 완주가 불가능했다. 실기기 수치가 아니므로 로딩 체감 문제로 단정하지 않았다. 대신 ① 3장에서 소환·장판 실측, ② `STAGES` 설정 정적 대조, ③ 맵1에서 12장 보스 설정(무늬 12·기물 3·장판 5)으로 치환해 검증했다. 12장 맵 자체는 보스 등장 직후 화면까지만 확인(`30_s12_boss_arena.png`).
- **소리**: 실제 청취 불가(무음 헤드리스). `audio.info()`상 BGM `daegeum-buk`, 효과음 8종 로드 확인.
- **변주 원귀 3종의 세부 행동**(돌진 거리·투척 명중·자폭 피해): 생성만 확인. v0.23 QA에서 실측된 값 그대로일 것으로 보나 이번에 재측정하지 않았다.
- **사람의 손 제스처 감각**: 인식률은 합성 궤적으로 측정했다(떨림·속도 변화 포함). "정확한 획 0.80 기준"이 사람 손에 적절한지는 실기기 확인 필요.
