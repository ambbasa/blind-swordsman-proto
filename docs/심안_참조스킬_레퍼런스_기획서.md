## 4. 지금 남은 갭 (레퍼런스 대비 솔직한 진단)

1. **`@coldmountainlab`와의 차이는 "그림 밀도"** — 우리 바닥은 "이어지는 지형"이 됐지만(v0.43), 참고작은 절벽·찻집·처마가 **한 폭 그림**으로 완성돼 있습니다. 물체를 더 놓는 게 아니라, 지형 단면(절벽·물가)과 건축 띠(처마·좌판)를 그려 넣어야 메워집니다.
2. **모션은 "연결성"에서 아직 반 발짝** — v0.45에서 뼈대를 세웠으니 주인공은 해결됐지만, 몬스터·보스가 v0.46 완료 전까지는 2D 카드입니다. 또 8방향은 되지만 상체·하체 분리 회전(스트레이프)은 없습니다.
3. **스킬의 "읽히는 전조"가 없다** — 바닥 흔적은 들어갔지만, 참조한 LinearAbilty식 **장전→조준선→발사** 흐름과 리본 궤적이 없어 스킬이 "터지고 나서야" 보입니다.
4. **전투 수치의 문서화 부재** — 예비동작 0.34초만 수치화됐고, 적·보스 전 공격의 선딜/판정/후딜/파훼법 표가 없습니다. 보스전 1:1 패링을 만들려면 이 표가 먼저입니다.
5. **성능은 "측정"이 아니라 "체감 대응"** — v0.28 프레임 멈춤을 계측으로 잡았지만 상시 예산표가 없습니다. 30~50마리 SkinnedMesh(v0.46)는 이 표 없이는 회귀를 못 잡습니다.
6. **QA 자동화가 반쪽** — 510획·콘솔 0·SHA는 자동인데, **봇 주행 플레이**와 **시각 회귀 diff**가 없습니다. 참조 스킬(threejs-qa-release)이 정확히 그 두 가지를 요구합니다.
7. **실기기 프레임 미측정** — v0.39~v0.46의 프레임 수치는 전부 헤드리스 SwiftShader 값입니다.

## 5. 향후 고도화 로드맵 (v0.47 이후)

> 순서 원칙: **① 지금 진행 중인 것(v0.46)을 안착 → ② 전투의 뼈대(수치·텔레그래프) → ③ 성능·QA 자동화 → ④ 손맛·연출 → ⑤ 맵·UI 마감.** 각 단계는 그 자체로 배포 가능한 크기로 잘랐습니다.

### v0.47 — 몬스터 3D 안착 + 보스전 1:1 패링/역공 (창현님 발안)
- **선행**: v0.46 배포 후 30·45·50마리 스트레스에서 `SkinnedMesh` 마리당 2콜 유지 확인, 원거리 2~3프레임 갱신이 실제 CPU를 줄이는지 계측.
- **전투 수치표 작성** (`game-design-ai-practice` + `design-action-combat`): 보스 공격별 `선딜 / 판정 프레임 / 후딜(빈틈) / 사거리 / 파훼법(거리·회피·패링)` 표. 창현님이 제안한 "보스 공격 패링 + 생성 공격물에 타이밍 돌진 회피" 구조를 이 표 위에 올림.
- **패링 창**: 0.18초(±0.06) 시작값, `tap` 칼집 패링(이미 v0.16 구현)을 보스전용 리액션(경직 0.6초 + 역공 1회)으로 확장.
- **검증**: 결정론 전투 테스트(같은 시드·같은 입력 → 같은 결과), 패링 성공률 봇 측정, 보스 TTK 목표(예: 25~35초).
- **리스크**: 보스 1:1은 잡몹을 빼는 구조라 "뱀서류 재미"와 충돌. 보스전만 별도 아레나로 분리하는 현재 구조 유지 필요.

### v0.48 — 스킬 전조·선형 캐스팅 (`LinearAbiltyCastingThreeJS` 직수입)
- **3단 구조** 도입: `장전(0.35초, 발밑 원 + 조준 화살)` → `발사(리본 정점 셰이더 1장)` → `잔열(바닥 SDF 균열 8초)`.
- **파 캐스트 경계 원**: 보스 장판 예고를 "경계 두꺼운 원"으로 바꿔 **공간 크기**를 먼저 읽히게.
- **원소 각인 Lv3 해금기**를 이 연출의 무대로 사용(현재 원소별 바닥 흔적 `traces.js` 4종을 SDF로 승격).
- **검증**: 스킬 캐스팅을 **정지 프레임으로 캡처해 채점**(`game-dev-combat-skill-polish` 방식) — 시전 자세·궤적·피격 3박자가 같은 프레임에 있는지.
- **리스크**: 리본·SDF 셰이더는 저사양에서 비용 큼 → 품질 레더 3단 이하에서 텍스처 데칼로 폴백.

### v0.49 — 모바일 프레임 예산·QA 자동화 (`andrew_game_perf` + `threejs-qa-release` + `optimize-threejs-games`)
- **프레임 예산표**: 390×844·60fps(16.6ms) 기준 `drawcall ≤ 250`, `삼각형 ≤ 220k`, `포즈 텍스처 ≤ 310MB`, `JS tick ≤ 0.02ms/개체` — v0.45 실측(163콜·+18k)을 기준선으로 고정.
- **10패턴 전수 감사**: ⑦ dispose 누락, ⑧ 오브젝트별 드로우콜, ⑩ 가변 타임스텝 물리 우선.
- **봇 주행 테스트**: 스크립트 입력으로 1→12장 자동 주행(사망 시 재시작), 콘솔/404/프레임 수집.
- **시각 회귀 베이스라인**: 장별 기준 스크린샷 + 픽셀 diff 임계값.
- **실기기 측정**: 창현님 폰에서 `GPv2.fps()` 평균/최저 기록(헤드리스 수치의 실효 보정).

### v0.50 — 사운드·타격감 보강 (`threejs-gameplay-systems` game-feel + `build-game-audio-feedback`)
- **타격 3층**: 먹(저역 스러스트) + 베기(중역 스와이프) + 관통(고역 틱), 히트스톱 0.03~0.05초를 무기·스킬별로 표화.
- **스크린셰이크**: 방향성 0.12초·최대 3px, 보스 피격만 5px — reduced-motion 옵션 함께.
- **오디오 상태**: 전투 강도(잔몹/보스/참 발동)에 따른 음악 레이어 전환, 모바일 오디오 언락 점검.
- **검증**: 버스 덕킹이 이미 있으므로 레이어를 늘려도 잡음화되지 않는지 80회 몰아치기 하드햄머로 재측정.

### v0.51 — 맵 완성도 (`@coldmountainlab` 격차 메우기 + `3d-falling-leaves`/`four-seasons`/`mykonos-island-voxels` 원리)
- **지형 단면**: 절벽·물가 단면 띠, 강 건너 먼 마을 지붕 띠.
- **건축 띠**: 기와 처마·좌판·찻집 탁자·깃발을 물길 따라 배치(격자 프리셋으로 저작).
- **붓 터치 레이어**: 바닥 텍스처 위에 장별 붓 터치 1겹.
- **입자**: 1막 낙엽 / 6장 눈 / 12장 재 — 인스턴스 1배치로.
- **검증**: 참고작과 같은 구도(물길 곡선 + 원경)로 캡처 비교.

### v0.52 — UI 정리와 자체 채점 (`unslop` + `threejs-game-ui-designer` + `threejs-aaa-graphics-builder`)
