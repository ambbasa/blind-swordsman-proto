# 심안 캐릭터 모델링 방향: 원화의 검객을 전투 화면까지 유지하기

**결정: 지금은 모델을 다시 만드는 단계가 아니라, 기존 모델 위에서 원화의 채색을 재현하는 단계다.** 플레이어가 로비에서 본 검객과 전투에서 조작하는 검객을 같은 인물로 느끼는 것이 목표다. 확대했을 때 예쁜 것과, 작고 빠르게 움직일 때 읽히는 것은 별도로 검수한다.

이 문서는 다음 제작을 위한 방향서다. 기준 버전은 `18aa5c7`이며 아래의 새 채색은 배포된 기능이나 승인된 자산이 아니다.

## 1. 무엇을 기준으로 삼는가

| 기준 | 여기서 읽을 것 | 여기서 가져오지 않을 것 |
|---|---|---|
| [우리 로비 검객](../v2/assets/hero/lobby_hero_latest.webp)과 [캐릭터 일러스트](../design/character-concepts/ember-illustrations/) | 얼굴에 시선이 가는 순서, 도포 깃의 겹침, 허리끈·방울의 강조, 인물의 분위기 | 일러스트의 배경 안개·접지 그림자·역광까지 몸에 칠하지 않는다. |
| [주인공 4면도](../design/character-concepts/ember-guardian-mv/hero_mv/)와 [8종 제작 원화](../design/character-concepts/ember-guardian-mv/) | 앞·뒤·옆에서 안대가 어디로 이어지는지, 옷 경계와 문양이 어디에서 만나는지 | 시점별로 다른 그림자를 평균내 얼굴이나 깃이 번지게 하지 않는다. |
| [현행 주인공 GLB](../v2/assets/models/hero.glb) | 현재 얼굴·체형·도포·검, 관절 66개와 동작 8개. 이번 채색 작업의 원본 | 전 단계 실험 모델을 원본 삼아 보정을 누적하지 않는다. |
| [엠버 앤 블레이드 인물·전투 페이지](https://emberandblade.com/ko/) | 밝은 피부와 어두운 옷이 만나는 색면, 제한된 그림자 단계, 전투 크기에도 남는 강조색 | 펜릭스의 얼굴·의상·무기·체형은 가져오지 않는다. 원화와 게임 모델이 동일 파일이거나 특정 툴로 제작됐다고 가정하지 않는다. |

**참조가 충돌할 때:** 원화는 표현의 기준, 현행 GLB는 형상의 기준이다. 예를 들어 로비 그림의 밝은 안대와 현재 모델의 붉은 안대는 단순한 조명 차이가 아니다. 첫 후보에서는 현행 붉은 안대를 유지하고 얼굴·머리와의 명도 경계를 정리한다. 안대 색을 바꾸거나 끝단 메시를 늘리는 일은 별도 디자인 변경으로 구분한다.

## 2. 이전 시안에서 가져갈 교훈

- **각진 H 시안:** 비교 그림의 선을 얻으려고 팔·어깨·도포를 새 단면으로 만들자 선은 또렷해졌지만 인물이 달라졌다. 목각처럼 만드는 것은 우리 목표가 아니다.
- **채색·조명 시안:** 같은 몸체를 보존했지만 화면이 밝아지고 어깨와 이마에 밝은 조각이 생겼다. 사용자는 원본을 선호했다. 화면 전체의 밝기·채도 또는 외곽선 두께를 올리는 것만으로는 원화에 가까워지지 않는다.
- **유지할 것:** 원본과 후보를 같은 조건에서 비교하는 방식, 게임에 넣기 전 스킨·검·클립 보존 검사, 실제 전투 크기에서의 확인. 일반 로비는 일러스트로 두고, 회전·모션 검사는 개발자 모드에서 한다.

## 3. 첫 작업은 주인공 상반신 채색 한 장

몸 전체와 셰이더를 동시에 고치지 않는다. 얼굴·안대·교차 깃·한쪽 소매부터 작업해 원본과 비교한다. 이 작은 범위에서 차이가 보이지 않으면 8종 일괄 생성으로 넘어가지 않는다.

| 부위 | 원화에서 3D로 옮길 작업 | 되돌려야 할 징후 |
|---|---|---|
| 얼굴·안대 | 피부 기본색, 턱 아래의 큰 그림자, 안대의 위·아래 경계를 구분한다. 콧등과 턱의 방향은 적은 면으로 설명한다. | 안대가 머리 그림자에 섞이거나, 이마 한가운데 밝은 점이 시선을 뺏는다. |
| 보라 도포·밝은 깃 | 깃이 실제로 포개지는 순서대로 경계를 그린다. 소매 윗면은 큰 기본색, 겨드랑이와 접힌 안쪽만 그림자로 묶는다. | 천의 얼룩과 작은 주름마다 명암이 바뀌거나 깃이 떠 있는 테이프처럼 보인다. |
| 붉은 허리끈·방울 | 매듭과 늘어진 끈은 하나의 붉은 덩어리로 먼저 읽게 한다. 방울은 금빛 면과 국소 반사 한 곳만 사용한다. | 끈 전체가 발광하거나 금빛이 얼굴보다 먼저 보인다. |
| 검·손·신발 | 손과 자루가 겹치는 곳은 짧은 접촉선으로 분리한다. 검날의 넓은 면과 날 끝은 구별하되 기존 검 형상과 파지를 유지한다. | 정면에서 짧아 보인다는 이유로 검을 늘리거나, 가죽과 칼날이 같은 광택을 낸다. |

### Blender에서 실제로 하는 순서

1. **원본 고정.** 현행 GLB를 별도 작업 파일에 가져온다. UV·메시·리그는 유지하고 몸의 베이스컬러 이미지만 복제한다. 원본, 후보, 사용 원화, 카메라 각도를 기록한다.
2. **색 견본 만들기.** 피부·머리·도포·깃·끈·금속에서 대표색을 채취한다. 천부터 기본색/그림자색 두 면으로 시험하고, 필요한 곳에만 중간색을 더한다. 전신을 동일한 색상 수로 강제하지 않는다.
3. **UV 위에 다시 칠하기.** Blender Texture Paint 또는 UV를 내보낸 2D 편집기에서 큰 재질 경계를 먼저 그린다. 기존 텍스처의 잔노이즈를 단순히 선명하게 만드는 필터는 쓰지 않는다. 4면 투영은 밑그림으로만 쓰고 얼굴 옆에 손 색이 묻는 부분, 소매 안쪽, 목 뒤, UV 섬 경계는 회전시키며 직접 정리한다. 밉맵에서 틈이 생기지 않도록 섬 가장자리 바깥까지 색을 연장한다.
4. **안료색과 조명을 분리.** 베이스컬러에는 재질 고유색과 깃 아래 같은 고정된 겹침만 남긴다. 화면 한쪽의 광원, 금속 반사, 바닥에서 올라오는 빛은 굽지 않는다. 무조명 색상 보기에서 이미 피부·안대·깃이 구분되어야 한다.
5. **노멀·셰이더는 두 번째 변수.** 기본 후보는 원본과 같은 노멀·재질·조명에서 본다. 중립 조명에서는 괜찮고 게임에서만 하얗게 뜬다면 그때 [게임의 주인공 재질 처리](../v2/js/glbhero.js)를 조사한다. 얼굴의 모든 삼각형에 그림자가 튄다면 텍스처에 검은 선을 더 그려 덮지 않는다.
6. **선의 우선순위.** 첫째는 인물과 바닥의 외곽, 둘째는 머리/목·손/자루·깃/가슴의 겹침, 셋째는 장식이다. 밝은 깃과 남색 도포처럼 색 차이로 이미 분리된 곳은 검은 선을 추가하지 않는다. 전투 크기에서 손이 검은 점이 되면 선이 과하다.
7. **별도 GLB로 출력.** 이미지를 GLB 안에 넣고 새 장면에 재임포트해 파일 하나로 표시되는지 확인한다. 검과 외곽선이 사라지지 않았는지, 대기·걷기·베기·피격 동작이 기존과 같은지 본다. 이번 단계에서 Hunyuan 형상 재생성이나 고해상도 재추론은 필요 없다. 모델링 PC의 자원은 후보 한 개씩 반복 검수하는 데 쓴다.

## 4. 승인 방법: 조명이 좋아진 것과 채색이 좋아진 것을 구분하기

| 검수 | 비교 조건 | 통과 기준 |
|---|---|---|
| 원화 대조 | 원화·원본·후보를 동일한 머리 높이로 맞춰 앞과 ¾에서 나란히 본다. | 얼굴을 새로 디자인하지 않고 안대·깃·허리 매듭이 원화와 같은 순서로 읽힌다. |
| 고정 조명 A/B | 원본·후보 모두 같은 대기 프레임, 도포, 카메라, 노출. 무조명 색상 보기와 중립광 보기를 각각 저장한다. | **조명을 바꾸지 않아도** 후보의 재질 경계가 더 분명하다. 단순히 밝거나 채도가 높은 쪽을 채택하지 않는다. |
| 실제 전투 | 390×844에서 밝은 6장과 붉은 9장, 공격 직전과 검격 이펙트가 겹치는 순간을 비교한다. | 얼굴 확대 없이 주인공 위치와 공격 방향이 보인다. 등에서 도포가 바닥에 묻히거나 붉은 배경에서 허리끈만 뜨지 않는다. |
| 모션·기술 | 개발자 모드 `/v2/?dev=1`에서 정면·측면·후면과 동작을 확인한다. 같은 장면·기기에서 로딩, 파일 크기, 프레임 시간도 원본과 비교한다. | 텍스처만 바꾼 후보는 위치·노멀·UV·스킨 웨이트·검·클립 데이터가 원본과 같다. 색이 목·손목 이음매에서 끊기거나 움직일 때 깜박이지 않는다. |

**후보 한 개당 남길 자료:** 독립 GLB, 수정한 베이스컬러, 원화/원본/후보 비교 한 장, 실제 전투 캡처, 바꾼 것과 그대로 둔 것. 사용자가 원본을 더 선호하면 원본을 유지하고 부위별 차이를 기록한다. 기술 테스트 통과는 미술 승인과 별개다.

## 5. 주인공 승인 뒤 확장 순서

1. **주인공 한 종:** 상반신 비교 → 전신 GLB → 두 스테이지 실전 비교까지 끝낸다. 승인된 원본/후보 한 쌍을 이후 캐릭터의 기준으로 보관한다.
2. **미니언·헤비·스톤:** 같은 광원 아래 같은 거리에서 세 종을 한 화면에 놓는다. 미니언은 가는 팔다리와 빈 공간, 헤비는 어깨·몸통의 무게, 스톤은 석판의 큰 면과 틈이 먼저 읽혀야 한다. 종별로 형광색을 지정하기 전에 흑백·공격 준비 자세에서도 역할을 구분할 수 있는지 본다. 채색 후에도 겹치면 표시 크기나 모션 문제로 분리해 별도로 비교한다.
3. **막별 보스 4종:** 각 막 원화에서 대표 윤곽 하나, 강조색 하나, 공격 직전 보이는 부위 하나를 고른다. 도감의 확대 화면뿐 아니라 실제 배경·예고 이펙트 위에서 가독성을 본다. 주인공 팔레트를 복사하지 않고 색면과 선을 사용하는 원칙만 공유한다.
4. **채택·배포:** 승인한 종만 게임 모델로 교체한다. 모델 URL과 캐시 갱신, 새 브라우저/기존 방문자 환경의 로딩을 확인한 뒤 원본 복귀점을 남긴다. 이번 문서 업로드는 어떤 캐릭터도 교체하지 않는다.

기존 공정의 리깅·생성 환경은 [인수인계 문서](./SIMAN_HANDOFF.md), 전투 배경 비교 조건은 [스테이지 플레이 검수 기록](./qa/stage-scenery-playtest.md)을 참고한다.
